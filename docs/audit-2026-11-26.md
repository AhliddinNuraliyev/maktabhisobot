## 1. Umumiy holat

Arxitektura sog'lom: statik SPA (`index.html`) + Vercel serverless (`api/`) + Supabase (service_role faqat serverda).
Xavfsizlikning asosiy poydevori to'g'ri qurilgan: HttpOnly cookie, HMAC sessiya, `timingSafeEqual`,
Telegram imzo tekshiruvi, webhook HMAC + timestamp, replay himoyasi, atomik kredit RPC, RLS yoqilgan.
Bu — o'rtacha havaskor loyihadan ancha yuqori daraja.

Quyidagi muammolar biznes (pul), xavfsizlik va barqarorlik bo'yicha muhimlik tartibida.

## 2. KRITIK (P0) — darhol hal qilish kerak

### P0-1. Kredit himoyasi faqat brauzerda — bepul yuklab olish mumkin
**Fayllar:** `index.html:942`, `index.html:1523`, `index.html:1531-1534`, `index.html:2280-2283`, `choraklik.js:594,638`

Oqim quyidagicha:
```
mhCanDownload()      -> faqat AUTH.stats.credits (brauzer xotirasi) tekshiriladi
fayl generatsiya      -> PDF/Excel tayyorlanadi
saveBlob()            -> foydalanuvchi faylni OLADI
bumpDownload()        -> KEYIN /api/event chaqirilib kredit -1
```

Natijada uchta yo'l bilan pul yo'qoladi:
1. DevTools → Network → `/api/event` so'rovini bloklash. Fayl baribir yuklanadi, kredit kamaymaydi.
2. `AUTH.stats.credits = 999` (global scope'da) → cheksiz yuklab olish.
3. Internet uzilsa `bumpDownload` jim yiqiladi, kredit sarflanmaydi.

Qo'shimcha: barcha hisobotlar brauzerda generatsiya qilinadi, ya'ni faylni serverga topshirmasdan
himoya qilish printsipial imkonsiz. Hozirgi modelda "kredit" — faqat nazorat, himoya emas.

**Yechim (minimal):** yuklab olishdan **oldin** `/api/event` chaqirib kreditni rezerv qilish;
`402` qaytsa — generatsiya umuman boshlanmaydi. Xato bo'lsa `/api/event` bilan qaytarish (refund).
**Yechim (to'g'ri):** faylni serverda generatsiya qilib, imzolangan bir martalik havola bilan berish.

**Fayllar:** `api/telegram-login.js:35-60`, `api/send.js`, barcha endpointlar

Jonli tasdiqlandi — autentifikatsiyasiz, cheksiz:

Har chaqiruv `mh_bot_logins` ga yangi qator yozadi. Skript bilan daqiqada minglab qator yozib,

**Yechim:** IP bo'yicha limit (Vercel KV / Upstash Redis): `bot_start` — 10/daqiqa,
`/api/send` — 5/daqiqa, login — 20/daqiqa. Minimum: bir IP uchun ochiq `pending` nonce sonini cheklash.

## 3. YUQORI (P1)

### P1-1. Vaqtinchalik jadvallar hech qachon tozalanmaydi
`mh_bot_logins` va `mh_auth_nonces` o'sishda davom etadi. `supabase-billing-setup.sql:230-231,255-256`
da tozalash **faqat izoh** sifatida yozilgan, `vercel.json` da `crons` yo'q.
**Yechim:** Vercel Cron (kunlik) yoki Supabase `pg_cron`: `expires_at < now() - 1 day` o'chirish.

### P1-2. Excel kutubxonasi eski va zaif versiyada
`index.html:882` — `xlsx@0.18.5`. Bu versiyada ma'lum CVE'lar bor (prototip ifloslanishi, ReDoS),
foydalanuvchi yuklagan fayl shu kutubxona bilan parse qilinadi.
**Yechim:** SheetJS 0.20.3+ (`cdn.sheetjs.com`), yoki `exceljs` ga o'tish.

### P1-3. Barcha CSS/JS tashqi CDN'dan, SRI'siz
`index.html:77` (`cdn.tailwindcss.com`), `882-884` (cdnjs), `78-80` (Google Fonts).
- Tailwind CDN production uchun tavsiya etilmaydi: brauzerda CSS generatsiya qiladi (FOUC + sekin).
- CDN bloklansa (maktab tarmoqlarida tez-tez) — **butun dizayn yo'qoladi**, eksport ishlamaydi.
- `integrity` atributi yo'q → CDN buzib kirilsa, sayt orqali kod bajariladi.

**Yechim:** Tailwind'ni build vaqtida `style.css` ga chiqarish, `xlsx/jspdf` ni o'z domeningizdan berish.

### P1-4. Soft-404 va canonical muammosi (SEO)
`vercel.json:12` — barcha noma'lum yo'llar `200 + index.html` qaytaradi:
```
GET /yoq-sahifa-test-123 -> 200 text/html
```
Google uchun bu "cheksiz yumshoq 404" — indeks sifati tushadi.
Bundan tashqari `index.html:10` canonical har doim `https://maktabhisobot.uz/` — shuning uchun
`/bsb`, `/choraklik` alohida sahifa sifatida indekslanmaydi. `sitemap.xml` da `/chsb`, `/li`,
`/kuratorlik` umuman yo'q.
**Yechim:** yo'nalishga qarab canonical va `<title>` ni JS bilan almashtirish + sitemapni to'ldirish.

### P1-5. Replay himoyasi serverless'da ishonchsiz (fallback)
`api/_lib.js:230-249` — `mh_use_auth_hash` RPC topilmasa, jarayon ichidagi `Map` ishlatiladi.
Vercel'da har so'rov boshqa instansga tushishi mumkin → bir imzo bir necha marta ishlaydi.
**Yechim:** RPC majburiy qilish (topilmasa loginni 503 bilan to'xtatish), fallback'ni olib tashlash.

### P1-6. `upsertTelegramUser` — poyga holati
`api/_lib.js:183-205` — avval `SELECT`, keyin `INSERT`. Bir vaqtda ikki login kelsa,
`telegram_id unique` buziladi va biri **500** oladi.
**Yechim:** PostgREST `POST` + `Prefer: resolution=merge-duplicates` (haqiqiy upsert) yoki RPC.
